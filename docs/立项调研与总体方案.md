## 0. 执行摘要（先看这个）

1. **赛道成立**：弹幕互动玩法（抖音称"直播小玩法"，快手同名，虎牙/B站/斗鱼均有对应开放能力）生态成熟；抖音侧 7 万+挂载主播、350 万+付费用户，平台 2025 年持续加码扶持。
2. **跨平台是本方案的第一性原则**：同一套核心资产（玩法逻辑 + 美术 + 数值）通过**平台适配层**分发到 抖音 / 快手 / 虎牙 / B站 / 斗鱼 等平台。从业者实践已验证"一次开发、多端部署"是个人/小团队摊薄成本、放大概率的核心优势。架构上从第一天起就执行 **Core/Adapter 分离**（第 10 章）。
3. **⚠️ 最大风险是合规，不是技术**：执行**法律 > 平台规则双层底线**（2.0/2.1）——法律层：随机产出不可交易/不可回兑写进代码硬约束（赌博红线）、未成年人保护、主播话术红线；平台层：以最严平台（抖音）做"合规超集"——禁玩法内抽奖/竞猜、禁"抽奖/盲盒/礼盒"外显、随机性只允许两种报备模式。**"luckyDraw"不能做成真的抽奖游戏**，必须重构为"幸运主题 + 合规随机性"；同时付费设计执行**反"充钱大赏"七原则**（5.8）——助力值叙事、大额集体化、免费高光，规避催氪观感与监管风险。按最严标准设计后，向其他平台移植只需放宽、不需返工。
4. **商业模式清晰**：用户刷礼物 → 流水平台约 50%、主播侧约 50%，开发者从主播侧收取服务费（抖音/快手默认为总流水 8%，快手"可操作"玩法分成更高，虎牙需企业认证开通）。收益 = 服务费率 × **全平台所有挂载直播间的流水总和**——关键在主播供给数量，多平台直接放大水管数。
5. **推荐玩法定位**：**《幸运锦鲤》——国潮幸运题材的多阵营攻防 + 阶段式节奏玩法**，**无真人主播、Auto-Host 全自动主持**（自动导演 + TTS 播报 + 动态信息层 + 情绪音景，5.5）。免费弹幕入场、礼物按**价值档位**映射确定性增益（跨平台礼物目录不同，效果挂档位而非具体礼物）、抖音侧接入官方"幸运魔方"（1 钻破冰，付费破冰用户 +25.8%）。
6. **发行节奏（v0.6 调整：用户拍板）**：**抖音首发**（大盘最大 + 任务金/幸运魔方/聚光红利；**首日即半无人策略**对冲无人治理风险）→ **快手次之**（合规确定性最高，承接自运营双轨）→ 虎牙/B站（差异化补充）→ TikTok 国际版（仅远期观察）。供给侧双轨：自运营直播间矩阵（托底/样板）+ 挂机副业主播生态（杠杆主引擎，6.5）。**个人操盘快速路径**：软著用骨架代码加急申请（不等成品，2~4 周）与提案五线并行，阶段 0 压至 1~2 周。
7. **投入参考**：行业单玩法成本 15 万起；跨平台架构下核心开发 6~10 周 + 每个新平台移植 2~3 周（代码复用率目标 70~80%，增量成本主要在**运营**而非代码）。

## 1. 行业与平台现状

### 1.1 什么是弹幕互动玩法（直播小玩法）

- 开发者开发的互动内容，主播通过开播工具（直播伴侣/云启动/小程序）挂载，观众在直播间通过**弹幕、点赞、礼物**参与，玩法画面实时呈现在直播流中。
- 生态三方：**平台**（规则、流量、结算）、**主播/公会**（挂载开播，多需报白/公会渠道）、**开发者**（提供玩法，吃服务费分成）。
- 本质是"直播内容"而非"游戏"：无版号要求、无内购，唯一付费出口是直播间礼物打赏。

### 1.2 各平台均已开放对应能力（这是跨平台的前提）

| 平台 | 开放能力名称 | 形态 | 备注 |
| --- | --- | --- | --- |
| 抖音 | 直播小玩法 | exe（直播伴侣/移动云启动）+ 开发者服务端 | 生态最成熟，任务金/幸运魔方/小摇杆等官方工具最全 |
| 快手 | 快手小玩法 | ① PC 伴侣 exe ② 云平台 exe ③ **小程序**（手机端） | 技术路线最丰富；"可操作"玩法有更高分成档 |
| 虎牙 | 小程序平台（hyExt）+ 弹幕玩法 | 小程序 JS SDK + exe（本地/云启动）+ 对局 API | 开放 API 需企业认证 |
| B站 | 直播开放平台"互动玩法" | 开放平台项目 + 长连接事件 | 体量小、竞争小 |
| 斗鱼/YY/酷狗/QQ | 弹幕互动玩法 | 各自开放平台 | 跟进型市场 |

## 2. 合规红线分析（生死线：法律 > 平台规则 双层底线）

### 2.0 法律基线（国家法律层，优先级高于一切平台规则）

> 平台规则是"运营下限"，法律是"生存底线"。以下为设计期硬约束，逐条落进架构而非运营承诺。

| 法律/规范 | 对本项目的硬约束 | 设计侧保证 |
| --- | --- | --- |
| 《刑法》第 303 条（赌博罪/开设赌场罪） | 涉赌构成要件 = **财物输赢 + 抽头获利/可回兑**。一旦玩法产出可与现金互相兑换，即踩刑事红线 | 无现金/等价物回报；无用户间价值转移；随机产出**不可交易写入代码硬约束**（game-core 层禁实现交易接口），而非运营自律 |
| 《未成年人保护法》"网络保护"章 + 2022 年四部门《关于规范网络直播打赏 加强未成年人保护的意见》 | 禁止未成年人打赏；不得利用未成年人吸金；平台须提供退款通道 | 反幼龄美术（4.4）；不设未成年人向营销与话术；配合平台退款与身份核验机制 |
| 《网络主播行为管理办法》（2022） | 主播不得以诱导、欺骗方式骗取打赏，不得煽动高额消费 | **玩法提供的话术模板是内容工具，必须内置红线**（5.5）——主播违规会牵连玩法下架 |
| 《反不正当竞争法》/《规范促销行为暂行规定》 | 抽奖式有奖销售受严格限制；不得虚假宣传 | 不做任何现金/实物抽奖运营活动；外显效果描述与实际效果一致；概率真实且公示 |
| 《个人信息保护法》（PIPL） | 头像/昵称属个人信息 | 平台内最小化使用（仅榜单/演出署名）；**不跨平台做身份归并**；用户可通过平台渠道申请清除 |
| 税务 | 开发者服务费需开票结算 | 起步：个人主体 + 税局代开；G2 后升级个体户/公司对公开票（6.4） |

**一条总原则：所有随机产出不可交易、不可回兑、不可跨平台——这不是策划数值问题，是架构层的法律防火墙。**

### 2.1 抖音平台明令禁止（各平台中最严，作为平台规则层设计基线）

摘自《直播玩法准入规则》《内容规范》：

- **不得在玩法内设置抽奖、竞猜等机制**。
- **任何情况下不得在名称、外显上使用"抽奖""盲盒""礼盒"等包装**。
- 不得出现扎金花、百家乐、21 点、赌马等赌博方式；**不得展示老虎机、推币机、打鱼机、上分器、赛马等赌博器具**。
- 不得以现金或等价物回报诱导投入（涉赌）；不得收取与输赢相关的佣金。
- 禁止现金奖励活动；实物奖品建议 ≤200 元、话费 ≤50 元；奖励不可线下兑现。
- 点赞、评论、礼物行为**必须有对应的玩法效果，不可有概率无效果**。
- 不能设置纯付费维度的收集/兑换（如"累充 XX 送 YY"）。
- 概率必须对外公示；不得诱导未成年人消费。

### 2.2 随机性设计——只允许两种合规模式（需向平台报备）

**模式 A：送礼触发的随机性**
- 单款玩法**最多一种礼物**可用随机设定，其余礼物效果必须固定；
- 随机只允许**外观差异**，不允许数值、定位、数量差异；
- 随机效果必须是该礼物专属，不可与其他礼物效果重合。

**模式 B：送礼附赠的随机性资源**
- 单款玩法**最多一款礼物**可附赠"随机抽取资源"；
- 该资源**必须可通过免费行为获得**（不能仅付费）；
- 产出仅可用作**玩法内养成资源**，不可为可直接上阵/触发的消耗型内容；
- 具数值属性的内容**不可用户间交易**；最长保留 3 个月。

| 类别 | 禁用词示例 | 替代思路 |
| --- | --- | --- |
| 概念 | 游戏、玩家、背包、血条、赛季、排位、BUFF、CD、PVP、MOBA | 玩法、小伙伴/水友、行囊、气势/士气、好运状态、蓄力 |

### 2.4 对 luckyDrawer 的直接影响——"形抽奖，神合规"

**重构原则：把"赌的多巴胺"翻译成合规体验组件。**

| 传统抽奖的成瘾要素 | 合规实现 | 跨平台可用性 |
| --- | --- | --- |
| 付费开箱随机奖励 | **抖音官方"幸运魔方"**：1 钻随机 ≥1 钻礼物效果，平台补贴非付费用户（付费破冰用户 +25.8%） | 抖音独有；其他平台用自家低价位礼物破冰（虎牙有 0.1 虎牙币档） |
| 稀有度/SSR 收集欲 | **模式 A 随机外观礼物**：效果固定、皮肤随机（纯外观无数值差异）+ 稀有全屏演出 | 全平台通用 |
| 每日抽卡复访动机 | **模式 B 免费幸运星**：停留/点赞/弹幕攒"幸运星"→"星运阁"兑换养成资源与限定外观 | 全平台通用 |
| 大奖悬念时刻 | 确定性机制的悬念化演出（"锦鲤跃龙门"倒计时开奖式仪式） | 全平台通用 |
| 输赢翻转刺激 | 阵营攻防 + 最后 90 秒"鸿运时刻"效果翻倍（确定性规则） | 全平台通用 |

> **合规超集策略**：以抖音标准设计全部随机性、用词、未成年人保护；快手/虎牙/B站审核时只需按当地词表微调外显文案（词表进配置系统，见第 10 章），玩法本体零返工。

### 2.5 无人直播合规专项（v0.5 新增：本项目为无真人主播模式，生死线之二）

> 本玩法**无真人主播**，画面即玩法，全部主持功能由系统自动完成（5.5 Auto-Host）。这直接触达各平台"无人直播/挂机直播"治理区，规则差异如下：

| 平台 | 对纯玩法画面开播的态度 | 依据与风险 | 策略 |
| --- | --- | --- | --- |
| **快手** | **文档层面允许** | 快手官方技术选型文档明确："主播开播内容以『真人+直播小玩法推流画面』**或『直播小玩法推流画面』为主要直播画面**"均为合法形态；且其"云平台"路线（免设备开播）就是为轻主播设计的 | **次发平台（合规备援 ⭐）**：承接自运营双轨——抖音无人运营受阻时，纯无人重心转移至此 |
| 抖音 | 灰色，需谨慎运营 | 平台长期治理"无人直播"，打击对象是**录播/循环素材/无互动静默挂机**；实时互动玩法画面 + 实时弹幕响应属于实时内容，但纯静默有"低质直播"判定风险 | **首发平台（2026-10-16 用户拍板）**：首日即半无人——TTS 播报 + BGM + 动态信息流杜绝静默；黄金时段（4h）真人值班口播；挂机生态与自运营号同步起，任务金/聚光红利最早吃 |
| 虎牙/B站 | 中性偏严 | 各有无人直播治理，未见玩法画面豁免条款 | 跟进验证，不自运营起号 |
| 第三方工具（OBS+抓取） | **违规，弃用** | 历史上修狗云蹦迪类无人直播因此大量封号（调研原文）；官方生态就是平台"打不过就加入"的产物 | **规模化运营不走此路，无论收益诱惑多大**。唯一例外：Goal R3b 的 V0 验证轨（人拍板、限时、可弃置测试号、≤5 熟人、T0 后停用；数据仅作方向参考） |

**无人模式防封三原则（写进产品设计）：**
1. **内容实时性**：观众弹幕/礼物实时改变画面——这是"直播"而非"录播"的根本证据，架构上保证互动响应延迟可感知（<3s）；
2. **声音层永不静默**：TTS 播报 + 情绪 BGM + 事件音效三件套常开（静默画面是"挂机"判定的最直接特征）；
3. **变化性**：对局随机编排 + 好运主题轮换 + 节日事件，避免"循环播放"观感。

**账号矩阵红线**：同一主体批量注册开播账号属"批量账号运营"，平台打击项。自运营号建议 ≤3 个/主体，更多供给走"挂机副业主播"生态（6.5）。

## 4. C 端用户洞察

### 4.1 用户画像

各平台娱乐直播泛用户：年龄跨度大、多数非传统游戏玩家，"看直播顺手参与"。**无人模式下无主播粉丝团**，核心付费人群变为：玩法常客/连胜阵营的"老炮"（好胜、有沉淀）、好胜的中度参与者、被名场面演出吸引的冲动型用户；外围：白嫖党（点赞弹幕）、氛围党。生态模式（挂机主播）下则叠加原"粉丝团大哥"人群。

### 4.2 付费心理拆解（按优先级）

1. **胜负欲与对抗刺激**：一局 10~15 分钟高强度对抗，付费门槛低、上限高。
2. **存在感/荣誉**：ID 上榜、主播念 ID 感谢、专属称号、MVP 全屏演出——"为被看见付费"。
3. **可变奖励**：不确定性比确定性更激活多巴胺——必须走合规通道（随机外观/幸运星/平台破冰工具）。
4. **翻盘希望**：落后方永远保留"最后一分钟翻盘"可能，激发追加投入。
5. **社交归属**：阵营 = 临时部落；无人模式下社交围绕**开播账号的粉丝团 + 阵营连坐**形成（关注号→粉丝团→阵营气势加成，8.3）。
6. **情绪价值（v0.5 重写：无真人主播）**：原方案依赖"主播实时回应"作为付费闭环最后一环——无人模式下此环不存在，必须由**系统仪式感替代**：TTS 语音念 ID 感谢、全屏专属演出、进场通告、阵营集体欢呼音效。情绪供给从"人对人"改为"舞台对个人"——玩法即主播，演出即回应。
7. **即时爽感**：付费 → 3 秒内全屏可感知反馈。

### 4.3 转化路径与对应设计

`观看 → 3 秒看懂 → 免费参与（弹幕/点赞）→ 低价破冰（抖音幸运魔方 1 钻 / 虎牙 0.1 币礼物 / 快手低价礼物）→ 中额常态化 → 大额爆发 → 次日回访（幸运星/称号/连胜战绩）`

### 4.4 未成年人红线

- 画风**刻意规避幼龄化**（低幼画风实际吸引未成年人打赏，已被媒体点名、监管重点）；
- 不做诱导性话术；不提供任何现金/可兑现奖励；遵守各平台未成年人保护规范。

## 5. 游戏策划方案：《幸运锦鲤》（暂定名）

> 定位一句话：**国潮幸运题材的多阵营阶段攻防玩法——把"转发锦鲤求好运"的集体心智，做成直播间可参与的实时对战。**

### 5.1 题材与差异化

- **题材**：锦鲤、四叶草、烟花、舞狮、聚宝盆等"好运"意象的国潮美术（避开老虎机/转盘等赌具视觉）。"锦鲤"是中文互联网被验证的幸运符号，自带传播梗。
- **差异化**：市面对抗玩法无"幸运感"系统；我们把合规随机性做成核心记忆点而非附属功能。

### 5.2 核心循环（单局 12~15 分钟）

```
阶段一 蓄势（2 min）｜免费参与
  弹幕"锦鲤/神龟"选阵营入场，头像化身小鱼
  点赞 = 基础推力，弹幕口号 = 士气（免费行为均有确定效果✓）

阶段二 攻防竞速（8 min）｜付费发动机
  双方沿"好运河道"竞速推进 + 攻防拉扯
  礼物 = 确定性增益（召唤/加速/护盾/翻倍），组刷一键连发
  落后方触发"逆流机制"：确定性加成（非随机），保持翻盘悬念

阶段三 鸿运时刻（3 min）｜情绪顶点
  全场效果 ×2，领先方进入"跃龙门"倒计时演出
  天降"锦鲤雨"：在场参与者人人获得幸运星/外观碎片（确定性发放✓——
  稀有度差异只体现在下一局可携带的"福缘"外显，纯装饰、无数值差异）

结算（90~120 s，v0.5：内容化改造，不留死时间）
  胜方全员幸运称号 + 全屏烟花；MVP 专属全屏演出 + TTS 念 ID 感谢
  结算期同步播放"下局预告 + 彩头预告"，主播在场时可插话，无人时系统自动填充
  所有参与者获得幸运星（免费养成资源，模式 B）
```

**补充规则（v0.5）：**
- **中途加入**：任意时刻弹幕即可入场，即时获得当前阵营平均体型的小鱼 + 免费参与集体充能（不让迟到者裸奔）；
- **胜负唯一判定**：进度条先抵龙门者胜（单一胜负条件，3 秒可懂）；一切攻防动作只做两件事——加速己方 / 拖慢对方；
- **败方增益上限**：连败增益不叠加，上限 +10%（防"故意输球攒 buff"的逆向激励）。
- **终局潮汐（v0.7 补：计时耗尽的判定缺口）**：鸿运时刻结束仍无一方抵达龙门时，进入"终局潮汐"——双方获得等速自动推进（互动照常计入），先抵龙门者胜。胜负条件仍唯一（进度先达 100%），同时保留最后一刻翻盘悬念；同一结算帧双方同时越线时进度高者胜，完全相等记平局（双方均按胜方发放幸运星）。
- **锦鲤雨稀有度（v0.7 澄清）**："福缘"外显的稀有度由本局参与度确定性分档（非随机），否则构成第三条随机通道，违反 2.2。

### 5.4 幸运系统（合规四件套）

1. **平台破冰工具**：抖音幸运魔方（1 钻 + 官方补贴）；其他平台用当地 T0 档礼物做破冰主推。
2. **随机外观礼物**（模式 A，全玩法仅此一款）：T4 档锦鲤皮肤随机，稀有皮肤配专属全屏演出，制造"SSR 时刻"。**皮肤概率在玩法规则页公示**（金鲤 70% / 彩虹鲤 25% / 星耀鲤 5%，示例值，上线前过合规评审）；该"精英锦鲤"为此礼物专属单位，其他任何途径不可获得（模式 A 专属性要求）。
3. **幸运星 & 星运阁**（模式 B）：免费行为（停留 60s/点赞/弹幕）与**唯一一款礼物附赠**获得幸运星 → 兑换养成资源与限定外观（仅养成/外观、不可交易、3 个月保留、概率公示）。
4. **鸿运时刻**（确定性悬念演出）：规则透明 × 演出拉满。

### 5.5 自动化主持系统 Auto-Host（v0.5 全面重写：无真人主播）

> 无人模式下，原"主播侧设计"整体替换为 **Auto-Host 系统**——玩法自己当主播。这是本项目区别于市面所有玩法的核心工程，也是"无主播也能有节目感"的唯一保障。四个子系统：

**1. 自动导演（Director）**
- 按"触发→冲突→解决"剧本结构自动控制对局节奏：蓄势时长随在线人数弹性伸缩（人少短蓄势，人多拉满互动）；
- 逆流机制、鸿运时刻、锦鲤雨等节点由导演系统按战局状态自动编排（领先差、时间轴、参与度三因子），**制造剧本感的悬念而非纯定时器**；
- 空场处理（<10 人）：自动进入"表演赛"模式，AI 阵营互演示范玩法 + 循环教学，保证新进观众 30 秒看懂（对应冷启动凌晨档）。

**2. TTS 播报（Voice）**
- 战况播报：关键事件实时语音（"蓝方神龙入水！红方河道告急！"）；
- 感谢播报：礼物触发 TTS 念 ID + 事件描述（替代主播口播，是无人模式情绪供给的主力）；
- **播报密度自适应（v0.6）**：事件高峰自动合并播报（"蓝方连获三次加持！"），低谷期 BGM 主导、播报静默——防长时收听疲劳的第一道闸；默认低频档起步，内测 H2 实验校准（见第 12 章实验设计）；
- 欢迎与教学：新观众进场的规则速讲轮播；
- **播报文案红线（内置不可删，同原主播话术红线）**：禁消费指令、禁金额播报、禁对比羞辱、禁未成年人指向。TTS 文案与系统字幕共用同一词表过滤层。

**3. 动态信息层（Overlay）**
- 页面信息提示：规则贴纸（合规必留）、阶段引导大字、榜单距离可视化、集体充能进度——所有原"主播举牌子"职能界面化；
- **聊天驱动**：观众弹幕即聊天内容——弹幕关键词自动聚合上屏（"所有人都在喊 冲！"），让聊天本身成为画面内容。

**4. 情绪音景（Audio）**
- BGM 情绪系统：蓄势（轻快）→ 攻防（紧张）→ 鸿运（高潮）→ 结算（庆典）四段式音乐；
- 事件音效分层：T0 涟漪声 → T7 全场钟鼓——**声音永不停**（2.5 防封三原则之二）。

**主播兼容层（可选，服务生态模式）**：真人主播在场时可一键接管：话筒优先于 TTS、手速遥控加时、彩头系统解锁（表演类白名单）。即同一玩法**双模式运行**：无人 Auto-Host / 有人 Host-in-the-loop。

**收益仪表盘（自运营用）**：开播账号的本局流水、参与率、破冰率、下档任务建议——替代原"主播收益仪表盘"。

### 5.6 数值框架原则（初稿）

- 免费参与者贡献 ≈ 总进度 **20~30%**（v0.4 上调：与 5.7.D 集体充能联动——免费集体大招必须真能左右战局，否则"免费高光"沦为装饰；上限 30% 防止付费动力不足）；
- 付费分布（付费侧内部）：T0~T1 贡献 35%、T2~T4 35%、T5+ 30%——分布健康，避免纯大哥游戏；
- **大额软性防鲸**：T5+ 效果对单人边际递减（本局第 2 条神龙起，个人数值收益转为全队增益），既保护对局健康（碾压局 = 其他用户流失 = 付费停止），也构成"反钱包碾压"的产品证据；
- 逆流机制阈值：进度落后 20% 激活，"可追不可碾"；
- **阵营自动平衡（v0.5 补）**：入场人数失衡（如 7:3）时，人少方自动获得确定性产出加权（公示规则"人少力均"），防止"赢家通吃式站队"——阵营选择弹幕口令同权重分流 + 好友跟随形成虹吸是弹幕玩法常见崩坏点；
- 所有概率（T4 皮肤、星运阁）在对应界面公示（合规硬要求）；
- **数值全走服务端配置（config-as-data）**，跨平台调参不改包。

**内测数据基线假设（v0.5 新增，内测期校准——立项阶段无真实数据，以下为待验证假设而非承诺）：**

| 指标 | 假设基线 | 校准动作 |
| --- | --- | --- |
| 参与率（互动 UV / 看播 UV） | ≥8% | 低于则先修 3 秒法则与弹幕口令 |
| 付费破冰率（付费 UV / 看播 UV） | ≥1% | 低于则调 T0 档反馈强度与幸运魔方入口 |
| 单场人均停留 | ≥3 min | 低于则缩局至 10 min 并强化结算内容化 |
| 档位升级率（T0 用户升 T2+） | ≥15% | 低于则强化归因反馈与中段叙事 |
| 次日回访率（参与者） | ≥20% | 低于则前置跨局成长线（5.7.E 提前至 P0） |

### 5.7 C端激励锚点体系（v0.3 专项审核与补强）

#### 5.7.1 审核结论

用行为设计四层模型（**触发层-动机层-反馈层-沉淀层**）审核原有设计：

| 层 | 回答的问题 | 原有锚点 | 评级 | 缺口判断 |
| --- | --- | --- | --- | --- |
| 触发层（为什么是现在） | 制造付费时机 | 鸿运时刻倒计时 | **弱** | 只有一个高潮点，中局无付费时机；损失厌恶、对位刺激、从众压力全部未启用 |
| 动机层（为什么要送） | 提供付费理由 | 胜负欲/存在感/可变奖励/翻盘/归属/破冰低价 | **强** | 唯一缺口：中段档位（T1~T4）情绪叙事模糊 |
| 反馈层（送完发生什么） | 兑现付费感知 | 特效分级/榜单/TTS 感谢播报 | **中** | 缺**个人归因**——"我这一发改变了战局多少"不可见，阵营对抗的贡献天然被稀释 |
| 沉淀层（送完留下什么） | 制造回访理由 | 幸运星（受 3 个月合规保留限制） | **弱** | 无跨局成长线（等级/战绩/连胜/成就），昨天的我没有任何回来的理由 |

**总结论：够破冰，不够升级；够单局，不够回访。** 另有一个被低估的连锁风险：**免费行为（点赞/弹幕）在攻防阶段被礼物效果碾压后失效**——白嫖党中局流失 → 参与率下降 → 平台分发变差 → 且"大哥的存在感"失去观众基础（没人看，秀给谁）。激励系统必须同时服务付费转化和免费留存，二者是同一系统的两端。

#### 5.7.2 补强锚点明细（九项，均过合规校验）

**A. 个人归因反馈（P0·反馈层）**
- 每次送礼即时归因：画面弹出"你的礼物推进进度 +3.2%"（服务端确定性计算，非随机 ✓）；
- 个人战报：结算页展示本局贡献占比、最佳一波、击退次数；
- "关键先生"：打出决定性一击者，跃龙门演出中署名标注。
- 依据：付费核心心理是"我改变了战局"，阵营对抗天然稀释个人贡献，必须显式量化补回。

**B. 攀比三层（P0·触发层）**
- 双层榜：全局贡献榜 + 阵营内榜（蓝方第 3 和全局第 3 是两种动力）；
- 对位**事件化**播报（v0.4 修订：不播金额）："红方刚刚获得强力加持，龙门火光已现——蓝方，该集结了"——只报事件与战局含义，不公开任何用户的消费金额（金额播报是最典型的催氪外显，且涉及个人消费信息公开）；
- 榜单距离可视化（v0.4 修订：替代原"再送 X 可进前三"）：第 4 名榜单旁显示"距上一名还差 320 助力值"——用玩法内单位（助力值）呈现距离，**是否补足、如何补足由用户自己推理，系统不产生任何消费指令**。

**C. 中段档位情绪叙事（P1·动机层）**
- 每个档位绑定一个情绪词并贯穿演出设计：T0 参与 → T1 被看见 → T2~3 战术博弈 → T4 收藏时刻（SSR）→ T5~6 英雄感 → T7 仪式感。免费→1 元→20 元的每一步升级都要有一个明确的"情绪理由"。

**D. 免费行为全程有效（P0·动机+留存层）**
- **集体充能条**：全队点赞充能，满槽释放"全民锦鲤潮"（免费集体大招）；礼物可加速充能但**不可替代**——免费用户中局仍有抓手；
- 弹幕口令阶段化变化（蓄势口号/集结令/冲刺令），保持全程参与；
- 意义链：参与率 → 平台分发；观众基数 → 大哥存在感前提；免费用户 → 明天的破冰池。

**E. 跨局成长线（P1·沉淀层）**
- **幸运等级**：经验来自 参与场次 + 胜场 + 免费行为 + 贡献的**混合维度**（合规红线：不可纯付费维度 ✓），等级解锁表情/进场样式；
- 连胜与战绩：阵营连胜展示、个人跨局胜率/场次；
- 成就称号体系：确定性达成（非随机），规避模式 B"随机资源 3 个月保留"限制（提案时与平台确认成就类外显的保留规则）；
- 昨日荣耀：昨日 MVP 今日专属进场演出（时效性稀缺制造回访）。

**F. 战局悬念（P1·触发层）（v0.4 软化：原"损失厌恶"）**
- 榜位保卫：今日榜一在位时长外显，被超越时全场公告（这是榜单信息本身，非定向施压）；
- ~~优势告急推送~~ → 改为**战局悬念演出**：进度差被追近时，全屏演出"龙门火光逼近、河道湍流加速"——氛围渲染面向全场，**不做定向焦虑推送**（"你们的优势要没了快守"式的定向施压是媒体批评的核心催氪模式，弃用）；
- 时间压力保留在鸿运时刻倒计时（全场公平、规则透明的节奏压力是玩法性，不是催氪）。

**G. 从众触发（P1·触发层）**
- 全队连击战报："蓝方已连续送出 23 份心意"全屏播报（弹幕游戏付费爆发多是跟风式）；
- 直播间集体目标：全员共同解锁"龙门大典"（总参与门槛，免费点赞也计入）；
- 稀有名额（v0.4 修订：原"限量神龙"）：本局神龙 T6 全场 3 条、**单用户每局限 1 条**——送即有、先到先得、确定性 ✓；单用户上限防大哥独占，叙事包装为"每局只有三位有缘人得神龙相助"（福缘叙事，非抢购叙事）。

**H. 系统彩头（P2·动机层）（v0.5 重写：原主播彩头，无人模式改为系统彩头）**
- 连胜/达成集体目标时，系统自动解锁**全场彩头演出**：加时烟花秀、神龙巡游、全服幸运星雨——彩头由系统兑现且只含虚拟演出内容（合规：无现金/实物/线下兑现）；
- 生态模式下可叠加主播表演彩头（表演/才艺白名单内，禁低俗/身体惩罚/金额对赌）。

**I. 大额身份体系（P2·沉淀层）**
- 荣誉殿堂：混合维度成就（场次×胜场×免费行为×贡献，**禁止累计送礼解锁** ✓）解锁永久称号/头像框/进场特效；
- 高等级用户进场全屏通告（把大额身份变成日常可见的稀缺展示）。

### 5.8 反"充钱大赏"设计原则（v0.4 新增：付费叙事与体面化包装）

> 商业模式决定"礼物驱动"不可移除，但**"钱→进度"的直白映射是舆论、监管与用户疲劳的三重风险源**（法治日报"新型老虎机"批评、召唤悟空封杀先例）。本节七原则让付费从"充钱变强"迁移为"祈愿/加持/共创"，心理上更可持续，商业化上也更抗疲劳。

**原则 1：心理账户重构（叙事层）**
- 付费叙事 = "点亮好运 / 为队伍加持 / 祈愿"，外显计量单位一律用**助力值/心意/福缘**，任何界面永不显示金额；
- 心理账户从"赌博/军备竞赛"账户迁移到"打赏/祈福/娱乐"账户——后者用户心理负担低、决策更快、社会评价压力小（用户敢让朋友看到自己在玩）；
- 全部文案禁用"充值/消费/花钱/价格"字样（进词表系统）。

**原则 2：大额集体化（结构层）**
- T5+ 大额效果一律设计为"**集体增益 + 仪式演出 + 署名权**"：神龙为全队而战、鲤跃龙门是全直播间共同观看的"节目"；
- 大哥买到的是"点灯人"身份（署名、演出、感谢），不是个人数值碾压——存在感照给，碾压不给；
- 这同时解决三个问题：催氪观感、大哥碾压导致的对局崩坏、名场面传播素材。

**原则 3：战术薄层（能力层）**
- 档位间引入简单克制环（加速 ↔ 护盾 ↔ 爆发 ↔ 加速）+ 时机收益（鸿运时刻内使用效果更高）；
- "何时送、送什么"有选择感——付费者是**指挥官不是 ATM**；小付费者靠克制与时机也能打出高光时刻（胜任感是比数值碾压更持久、更体面的付费理由）。

**原则 4：免费高光（公平感层）**
- 集体充能大招必须真实左右战局（免费贡献目标 20~30%），释放时机由全队免费参与度触发；
- 免费用户同样有"关键先生"资格（锦鲤雨人人有份、集体目标人人署名）；
- "不花钱也能赢一次"是反"纯钱包对战"舆论的最硬产品证据，也是未成年人/媒体风险的减压阀。

**原则 5：软性防鲸（对局健康层）**
- 单用户每局大额名额限量（神龙 1 条/人）+ 边际递减转全队增益（5.6）；
- 商业逻辑：碾压局 = 其他用户流失 = 付费停止，防鲸不是道德姿态而是收入保护。

**原则 6：非金钱承认体系（身份层）**
- 气氛组榜（弹幕/点赞榜）与贡献榜**并列同屏展示**；
- 免费称号池与付费档位称号同稀有度体系；
- 让"被看见"不完全等于"花钱"——认可的来源多元化，付费才不显得是唯一出路。

**原则 7：催氪红线（文案层硬禁清单，进词表系统强制过滤）**
- 系统文案禁：消费指令（"再送 X 可…"）、金额播报（"XX 送出 199"）、对比羞辱（"榜一都比你努力"）、稀缺恐吓（"最后 1 个名额马上下架"式倒计时促销话术）；
- 时间压力只允许来自玩法节奏本身（鸿运时刻倒计时——规则透明、全场公平），不允许来自营销话术。

**与 5.7 锚点的关系**：5.7 回答"锚点是否够"（转化阶梯无断点），5.8 回答"锚点是否体面"（每个锚点在法律与舆论安全区内）。二者交集即最终设计边界：**每个付费锚点必须同时通过 5.7 转化检验和 5.8 七原则检验**。

### 5.9 GDD 数值框架 v1（v0.6 新增：从"原则"到"数"）

> ⚠️ 本节全部为**示例数值（v1）**，走服务端配置，内测期按 5.6.1 基线校准后出 v2。目标：提案可附、开发可依、平衡可验。

**① 胜负公式与进度模型**

- 胜负 = 进度条先达 100%（8000 助力值当量/边）；
- 推进速率 = 免费推力（点赞/弹幕，线性小额）+ 集体充能爆发（周期性大额）+ 礼物推力（档位助力值）− 对方压制（克制/单位效果）；
- 阶段速率权重：蓄势 2min 承载 0~5%、攻防 8min 承载 5~85%、鸿运 3min 承载 85~100%（×2 效果期，节奏前松后紧）。**v0.7 落地方式**：各阶段设进度上限（蓄势 ≤5%、攻防 ≤85%、鸿运起可达 100%，配置项 `progressCeil`）——超出上限的推进被钳制，保证三阶段节奏必然完整呈现，基准局约 10~12 分钟（含结算）。

**② 助力值经济（免费 25% / 付费 75% 的落地）**

| 档位 | 助力值/个 | 换算检验（≈55~60 助力值/元） | 克制属性 |
| --- | --- | --- | --- |
| T0 | 25 | 幸运魔方期望值 ~0.4 元 | — |
| T1 | 100 | 1.9 元 ✓ | — |
| T2 | 260 | 5.2 元 ✓ | **加速**（克爆发） |
| T3 | 520 | 9.9 元 ✓ | **护盾**（克加速） |
| T4 | 1050 | 19.9 元 ✓ | **爆发**（克护盾）；皮肤随机款 |
| T5 | 2600 | 52 元 ✓ | 增益（全队） |
| T6 | 5200 | ~90 元 ✓ | 爆发·大型（每局 3 条/人限 1） |
| T7 | 13000 | ~120 元+（各平台顶档） | 演出+直接推进 12% |

- 免费侧 2000 助力值/边 = 点赞弹幕 ~500 + 集体充能 4~5 次爆发 × 300~375（**免费贡献的大头**，5.7.D 落地）；
- 基准局双侧合计 ~15000 助力值，其中免费 ~4000 → 付费 ~11000 ÷ 57 ≈ **~190 元流水/局**（v0.7 修正：原 260~280 元把免费助力值计入了流水；推导链见 7.5）。

**③ 克制环数值（剪刀石头布，5.8 原则 3 落地）**

```
加速(T2) ──克──▶ 爆发(T4/T6)   加速期间所受压制效果 −50%
爆发(T4) ──克──▶ 护盾(T3)      精英锦鲤咬断护盾（护盾提前失效）
护盾(T3) ──克──▶ 加速(T2)      护盾存在时对方加速无效（冲势抵消）
```

- 被克方效果 −50%，克制命中时全屏提示"巧！"（战术高光时刻）；（v0.7 统一口径：上图"护盾存在时对方加速无效"按 −50% 执行，三边克制同强度）
- 护盾吸收下一次压制并破碎；由于压制只来自爆发类（精英锦鲤/神龙，克护盾），实际吸收比例 = 1 − 50%——爆发打在护盾上仍有一半压制生效；
- 时机层：鸿运时刻内全效果 ×2（已有）→ "何时送"与"送什么"构成策略薄层。

| --- | --- | --- | --- | --- |

**⑤ 阵营平衡算法（公示规则）**

- 人数因子：`w = clamp((N_多 / N_少)^0.4, 1.0, 1.35)`，人少方全部产出 ×w（"人少力均"，规则页公示）；
- 逆流机制：进度差 ≥20% → 落后方产出再 ×1.25；差回落至 <10% 移除；
- 连败增益 +10% 封顶不叠加（已有）。

**⑥ 边际递减（防鲸，5.6 落地）**

- 单用户本局第 2 件 T5+ 起：个人推进部分 ×0.7，**差额自动转为全队平分增益**（总值不变、结构转移——大哥的存在感照给，碾压不给）。

**⑦ 充能释放（v1 简化）**

- 满槽自动释放（300~375 助力值爆发 + 全屏"全民锦鲤潮"）；v1.1 内测后评估改由"本队免费贡献最高者"手动择时（免费用户高光时刻，5.8 原则 4 深化）。
- 礼物可加速充能，但每个充能周期内礼物贡献 ≤50% 槽位（"可加速不可替代"，5.7.D 落地）。

**⑧ 助力值与进度分离（v0.7 新增：修复数值自相矛盾）**

v0.6 表中 T6=5200、T7=13000 助力值，而胜负线仅 8000/边——单件 T7 即可独立终结对局，直接违反 5.8 原则 2/5（大额集体化、不给碾压）。修正为两套量：

| 量 | 用途 | 规则 |
| --- | --- | --- |
| **助力值**（贡献分） | 榜单、个人归因、成就 | 按上表②（与价值成正比，大哥"存在感照给"） |
| **进度**（胜负推进） | 进度条 | T0~T3 = 助力值（正常效率），T4 1000（受单件上限，原 1050）；**T5+ 设进度上限**：T5 1000 + 全队强化、T6 800 + 压制、T7 960（12%）+ 演出 |

- 单件礼物进度上限 ≤12.5%（1000/8000）——任何单件礼物不能独立决定胜负；
- 影响声明（config rules 要求）：T5+ 的"进度/元"降至 T0~T4 的 15~35%，等效于更强的软性防鲸；对 H3（流水上限）偏保守，对 H2 无影响；**数值方向属 L2 人审批项**，内测按 H3 激进档可放宽上限；
- 助力值↔元的换算率（≈57/元）仅内部使用，**不对外公示**；榜单分含免费贡献与边际递减，不可被稳定反推为金额。

### 6.5 运营模式双轨（v0.5 新增：无人模式下的两条供给路线）

> 无真人主播 ≠ 只能自己开播。供给侧有两种玩法供给方式，**建议双轨并行**：

**轨道 A：自运营直播间矩阵（控盘型）**
- 开发者自有账号（≤3 个/主体，防批量账号判定）挂玩法开播，Auto-Host 全自动；
- 收益结构见 7.5——单直播间拿满主播侧，但天花板 = 自有账号数 × 自然流量；
- 适用：冷启动验证、showcase 数据房；纯无人自运营重心在快手（抖音侧执行半无人）。

**轨道 B：挂机副业主播生态（杠杆型）⭐ 主增长引擎**
- 目标人群：不想/不会才艺的副业挂机主播（"一天赚几十块"人群，真实存在且庞大——玩法全自动意味着他们**零能力门槛**，完美匹配）；
- 玩法对他们的价值：挂机即开播、Auto-Host 替代所有主持工作、收益仪表盘透明；
- 供给获取：任务金投放 + "挂机也能开播赚钱"的精准话术渠道（副业社群）；
- 收益结构：开发者从每个挂机主播流水中收 X% 服务费（经典杠杆模型，8% × N）；
- **风险共担**：挂机主播的留存取决于单位时间收益——需保证稳定的小时流水下限（冷启动期可用任务金托底），否则矩阵速溃。

**双轨配比建议**：冷启动 A:B = 1:1（自运营号打样 + 10~20 个挂机主播铺量）；增长期 B 为主；A 常设 2~3 个官方样板间。

## 7. 收益机制（跨平台版）

### 7.1 分成结构（以抖音为基准，各平台同构）

```
用户礼物流水 100%
 ├─ 平台 ~50%
 └─ 主播侧 ~50%
     └─ 开发者服务费 X%（抖音/快手默认 8%，可自定）
         → 主播实际到手 = 流水 × (50% − X%)
```

- 开发者收益 = Σ(各平台 X% × 各平台挂载直播间流水)——**多平台 = 水管数翻倍**。
- 结算：普遍月结 N+1，需对公开票（又一个公司主体的理由）。

### 7.2 X% 定价策略

| 阶段 | 建议 X% | 逻辑 |
| --- | --- | --- |
| 冷启动 0~3 月 | **5~6%**（低于默认） | 主播选玩法看"火不火 + 自己赚多少"，让利换挂载量 |
| 成长期 3~12 月 | 8% | 对齐行业默认，靠数据说话 |
| 成熟期 | 8~10% | 供给稳定后适度回收 |

> 每平台独立执行此曲线；快手若走"可操作"高分成档，单独测算。

### 7.3 抖音任务金激励（2025 现行，其他平台各有对应）

| 类型 | 条件 | 比例 | 上限 |
| --- | --- | --- | --- |
| 基础任务金 | 全量上线 4 周后，周日均流水 ≥2 万 | 周流水 3% | 5 万/周/账户 |
| 新玩法任务金 | 上线前 4 周，按每 7 天流水 | 3%~5% | 5 万/周/玩法 |
| 优选任务金 | 优选玩法上线 28 天后，周流水 ≥10 万 | 3% | 5 万/周/玩法 |

- 任务金**不可提现**，只能发布主播任务（开播/登榜），需现金配资（创新玩法 开发者:平台 = 1:10）。
- 任务金是获客杠杆而非利润，计入 CAC 预算。

### 7.4 收益测算（三档情景 × 单平台，多平台按比例叠加）

假设：中小主播单场（4h）流水 2000 元、日均 1 场；腰部 1 万；头部 5 万+。

| 情景 | 挂载主播数/平台 | 日总流水 | 开发者日收入（8%） | 月收入（单平台） |
| --- | --- | --- | --- | --- |
| 冷启动 | 20 | 4 万 | 3200 元 | ~10 万 |
| 稳定期 | 100 | 30 万 | 2.4 万 | ~72 万 |
| 爆发期 | 300+ | 130 万 | 10 万+ | 300 万+ |

**跨平台叠加示例**：稳定期 抖音 100 主播 + 快手 60 主播（日 18 万流水）+ 虎牙/B站 40 主播（日 8 万）→ 合计日流水 56 万，开发者日入 ~4.5 万，月 ~135 万——而**玩法开发成本只发生一次**。

> 现实提醒：冷启动 20 个稳定主播/平台是最难的一关；运营成本随平台数线性增长（见 8.4）。

### 7.5 无人模式收益结构与财务现实（v0.5 新增）

**双轨收益结构：**

| 轨道 | 收益公式 | 特性 |
| --- | --- | --- |
| A 自运营矩阵（≤3 号/主体） | 单直播间 ≈ 流水 × 50%（自播自结，服务费率对己设 0） | 单房间收益是生态模式的 ~6 倍，但房间数与自然流量双天花板 |
| B 挂机主播生态 | 8% × N 直播间（经典杠杆，同 7.4） | 主增长引擎；瓶颈是挂机主播的单位时间收益（不达预期矩阵速溃，用任务金托底冷启动） |

**自运营收益推导链（v0.6：由 5.9 数值框架推导，替代拍脑袋）：**
`基准局付费助力值 ~11000（双侧 15000 − 免费 4000）÷ ~57 助力值/元 ≈ 190 元/局 → 局均 ~15 min（含结算）→ 满载时均 ~760 元 → 日等效满载 ~1.8h（流量曲线折算：仅黄金时段接近满载，凌晨/日间局流水远低于基准局）→ 基准日流水 ~1400 元/号 → 3 号 × 50% ≈ 2100 元/日托底`

> v0.7 修正：v0.6 链条"时均 1290 × 等效满载 11h"实得 ~1.4 万/日而非 1400，两处数字相差 10 倍；且免费助力值被计入流水。保留 1400 元/号（与 8.6、敏感性表一致），改为显式假设"日等效满载 ~1.8h"——**这正是 H1/7 天实测要校准的核心参数**。

**敏感性三档与决策规则（内测前先按悲观档做预算）：**

| 情景 | 日流水/号 | 3 号日收益（50%） | 触发的决策 |
| --- | --- | --- | --- |
| 悲观 | 400 元 | 600 元 | 自运营降级为纯样板间，主押生态轨道 B |
| 基准 | 1400 元 | 2100 元 | 按双轨并行推进 |
| 乐观 | 3000 元 | 4500 元 | 增设第 2 主体（合规注册）扩号 |

**自然流量实测 SOP（P0 执行，7 天）**：蹲点 5 个同类无人玩法直播间 × 3 时段（黄金/日间/凌晨）× 记录在线人数、弹幕条数、礼物频次（按档位估算流水），输出小时曲线 → 校准上表。

**财务现实清单（v0.5 补，此前测算未覆盖）：**
- **退款代扣**：未成年人退款在结算前由平台代扣，峰值月按流水 3~5% 预提坏账；
- **现金流错配**：任务金配资现金先行垫付，收入月结 N+1 滞后 30~60 天——预留 ≥2 个月运营现金；
- **税费**：服务费开票，一般纳税人现代服务业 6% 增值税（小规模 3%/优惠期更低，按主体确认）；
- **任务金 ROI 闭环**：每次投放独立归因，ROI < 1 连续 2 周即停投换渠道（任务金是 CAC 不是收入）；
- **24h 云运行成本**：无人模式常驻满载，服务器/云启动成本比生态模式高约 40%，计入单房间单位经济模型。

## 8. 引流与增长策略（跨平台版）

### 8.1 供给侧（主播）——增长的命脉

**漏斗：公会报白 → 任务金吸引 → showcase 转化 → 口碑扩散**

1. **公会合作（每平台第一优先）**：报白/挂载权限多在公会。上线前每平台锁定 2~3 家中型公会，谈定向扶持。
2. **任务金投放**：抖音任务金（1:10 配资）发布开播/登榜任务；其他平台用对应激励资源。Top50 玩法 80% 在用任务金，贡献 60% 开播与流水。
3. **showcase 冷启动**：集中有限主播资源打 1~2 个标杆直播间，把"这玩法能赚钱"的数据给公会商务看，招募滚雪球。
4. **主播冲榜周**：开发者自出资奖金池，登榜主播瓜分。

### 8.2 需求侧（观众流量）

1. **平台分发逻辑**：玩法数据（互动率/停留/付费）越好 → 直播间自然推荐越多 → 更多主播选择——**数据即投放**。
2. **平台扶持计划**：抖音聚光计划（冲"新形态+高品质"评测拿 S 级资源）；快手/虎牙对应活动。
3. **官方工具接入即增益**：抖音幸运魔方/玩法助手/小摇杆进阶版；快手底部栏/连屏；虎牙对局任务模式。
4. **内容侧**：官方抖音号 + 快手号发布名场面集锦（跃龙门/MVP/稀有皮肤"名场面"），锦鲤梗天然可传播。**v0.7：名场面自动剪辑由 P2 提前到 P2 内测期**——agent 生产模式下边际成本近零，且对 1 人团队是唯一可规模化的内容获客渠道（结算高光帧 → 自动出片 → 人 L2 抽验后发布）。

**营销与招募合规（v0.7 新增）：**
- 招募文案禁收益承诺（"挂机日赚 XX""躺赚"）——虚假宣传风险（2.0 反不正当竞争），且平台对"挂机赚钱"话术敏感；改为"零才艺门槛的互动开播工具 + 收益看板透明"；
- 所有营销物料（短视频字幕、社群帖、官方号简介）过同一词表；对外名称统一"幸运锦鲤"，**不用内部代号 luckyDrawer（= 抽奖）**；
- **平台分流**：抖音侧招募"半无人主播"（黄金时段在场口播，Host-in-the-loop 模式）；纯挂机主播引导至快手（无人合规确定性高）——避免把抖音无人治理风险转嫁给生态主播、造成封号即流失。

### 8.3 留存侧

- 每日幸运星签到回访；限定外观按"好运主题"轮换（外显避开"赛季"字样）；
- 粉丝团等级 → 阵营初始气势加成（联动各平台粉丝团体系）。

### 8.4 多平台运营成本模型（关键认知 ⚠️）

| 成本项 | 首发平台 | 每个新平台 |
| --- | --- | --- |
| 玩法开发 | 100% | **20~30%**（适配层 + 提案过审 + 布局档案） |
| 公会/主播关系 | 100% | **~80%**（独立生态，几乎不可复用） |
| 任务金投放预算 | 100% | ~60~100% |
| 客服/主播培训 | 100% | ~50% |

→ **结论**：代码复用率高，但增长主力（公会运营、任务金）基本每平台重建。扩张节奏必须与现金流匹配：**首个平台跑到周日均流水 2 万（基础任务金门槛）后再开第二平台**。

**运营人力现实（v0.5 补）**：1~2 人团队的活跃运营上限约 30~50 个挂机主播（超出后响应/维护质量崩坏）——7.4"稳定期 100 主播"需在团队扩至 3~4 人（+1 专职运营 BD）后达成，招聘成本计入阶段预算；在此之前收益天花板以 50 号 × 实际场均流水核算，勿按 100 号线性外推。

### 8.5 反作弊、防刷与内容安全（v0.5 新增：无人模式与任务金生态的必然配套）

**防刷（钱的问题）：**
- **公会互刷/小号自刷**：为冲任务金门槛或榜单奖励自充值——识别特征：送礼账号集中（同公会/同批注册）、付费时间窗集中、退款率异常；处置：任务金核算前置风控审核，异常房间流水剔除（与平台风控规则对齐，避免"骗取任务金"取消资格）；
- **机器人弹幕**：虚假参与率骗平台分发——参与率统计剔除重复文本/高频同文案弹幕。

**内容安全（合规的问题）：**
- 用户昵称/头像上屏（榜单、署名、进场通告）前过平台内容安全接口 + 本地词表，违规昵称自动打码降级（"锦鲤\*\*\*"）；
- Auto-Host 全部机器输出（TTS 文案、字幕、弹幕聚合上屏）统一走 10.5 词表系统——**机器嘴比人嘴更容易全量审计，这是无人模式的合规优势**。

### 8.6 挂机主播单位经济与客服 SOP（v0.6 新增）

**单位经济模型（每个挂机主播，冷启动决策依据）：**

| 项 | 假设值 | 备注 |
| --- | --- | --- |
| 获客成本 CAC | 80~150 元/人 | 任务中心激活奖励（官方渠道最精准）> 副业社群贴 > 招聘渠道 |
| 单间日均流水 | 300~600 元 | 低于自运营号（挂机主播自身流量更弱） |
| 开发者日收益 | 24~48 元/间（8%） | — |
| 回本周期 | 2~6 天 | — |
| 留存假设 | 半衰期 ~45 天 | LTV/CAC ≈ 5~10x，健康 |
| **干预线** | 单间时流水 < 15 元 × 连续 3 天 | 触发流失预警 → 任务金定向续投 / 主动降级维护 |

**客服 SOP（1 人兼职承载 ~50 间）：**
- 分级 SLA：房间级问题（开播中断/数据异常）**2 小时**响应——开播中断 = 收入中断，最优先；用户侧问题 24h；
- Top 客诉预案：幸运星未到账（对账接口自动核验+补发）、称号丢失（数据回档）、排名争议（战绩可查接口）、退款（一律转平台官方通道，不私下处理）；
- 工具：FAQ 知识库 + 半自动工单 + 战绩自助查询页。

## 10. 跨平台技术架构（v0.2 重写）

### 10.1 总原则：Core/Adapter 分离，从第一行代码开始

```
┌─────────────────────────────────────────────────┐
│                   玩法客户端 (Cocos Creator 3.8+, TS) │
│  presentation（演出/特效/UI）                       │
│  client-core（对局渲染状态机，平台无关）                │
│  platform-bootstrap（每平台启动器/SDK 桥：            │
│    douyin-boot / kuaishou-boot / huya-boot / bili-boot）│
│  Layout Profiles（每平台布局档案，数据驱动）            │
└──────────────┬──────────────────────────────┘
               │ 统一 WebSocket（自有网关 或 平台网关）
┌──────────────┴──────────────────────────────┐
│                   玩法服务端 (Node/Go)                │
│  platform-adapter（每平台一个实现，实现同一接口）        │
│   ├ 鉴权/房间绑定（抖音 token 换 room / 虎牙 JWT /     │
│   │  B站身份码 / 快手 code2Session）                  │
│   ├ 数据任务开启（抖音按 msg_type 逐个开任务/置顶礼物）   │
│   ├ 指令接收（HTTP 回调 / 平台长连接 / WS 订阅）        │
│   ├ 对局上报（虎牙 startBattle/heartbeat/endBattle；   │
│   │  抖音结算上报）                                  │
│   └ 推送网关（自家 WS，或抖音云 WS 网关）                │
│  event-normalizer → 统一事件模型 LiveEvent             │
│  game-core（平台无关：房间状态机/数值/经济/排行/防作弊）    │
│  config-service（礼物档位映射/布局档案/词表/数值，全热更） │
└─────────────────────────────────────────────┘
```

### 10.2 统一事件模型（normalizer 的目标格式）

```ts
type LiveEvent =
  | { type: 'comment'; user: User; text: string; msgId: string; ts: number }
  | { type: 'like';   user: User; count: number; ts: number }
  | { type: 'gift';   user: User; giftTier: Tier; valueFen: number; count: number; combo: number; msgId: string; ts: number }
  | { type: 'follow' | 'join' | 'fanclub' | 'share'; user: User; ts: number }

interface User { id: string; nick: string; avatar?: string; badge?: string; fansLevel?: number }
```

- **价值归一化**：`valueFen`（分）为 canonical 单位；每平台维护 礼物ID→分 换算表（配置热更）。
- **去重**：各平台 msgId 语义不同（虎牙有 transactionId 概念、抖音有 msg_id），normalizer 统一产出幂等键。

### 10.3 各平台接入要点备忘

| 平台 | 关键链路 | 特别注意 |
| --- | --- | --- |
| 抖音 | token→room_id→逐 msg_type 开推送任务→礼物置顶→HTTP 回调→WS 推客户端；可选**抖音云**部署（免鉴权/内网专线/免备案/防 DDoS） | 置顶 ≤6 款；幸运魔方有专属 sec_magic_gift_id 字段 |
| 快手 | 开放平台 app_id/secret→code2Session→access_token→互动消息推送（评论/点赞/送礼/关注/分享/粉丝团/超粉/贵族） | 压测硬指标：单房间聚合 1000qps、全局 4200qps、P995<1s；小程序路线包体/首包限制 |
| 虎牙 | hyExt JS SDK（onBarrageChange/onGiftChange…）+ 开放 API（JWT 鉴权）+ 对局 API（startBattle→2~3s 心跳→endBattle） | 开放 API 需企业认证；对局与业务对局必须一一对应 |
| B站 | 开放平台创建项目→身份码绑定→长连接订阅弹幕/礼物/进场 | 事件字段与抖音/虎牙差异较大，normalizer 重点覆盖 |

### 10.4 客户端技术选型论证

- **Cocos Creator 3.8+（TS）**：唯一同时满足 抖音 exe / 快手 exe + **快手小程序（要求 cocos≥3.7）** / 虎牙 hyExt + exe / B站 的引擎；H5 导出为 Web 端留口；团队招聘容易。
- **构建目标决策（2026-10-16 拍板）：原生 exe 唯一构建目标先行**——平台文档明示路线、提案零接受度风险、单路线降低 2-3 人团队复杂度。**web 版（Cocos web 构建 + WebView2 轻壳）后置为成本优化选项**，触发条件：G2 后实测单房间 24h 云成本占流水 >15%，或快手小程序路线提上日程（web 构建近直迁）。评估时需确认平台对壳包 exe 的接受度 + 同代码压测（渲染≥30fps/内存≤350MB）。注意：若走 web 壳，**必须用 WebView2（系统自带 Edge 内核），禁用 Electron**（捆绑 Chromium +150MB，比 native 更重，违背轻量化初衷）。
- 美术画风联动：**2.5D**（成本档位 + 渲染余量 + 保留未来 web 切换自由度）。
- 多线程/同屏人数：从 MVP 起按"单房间 5 万 UV 参与、同屏高密度单位"设计渲染与逻辑分帧（鱼蛙狂飙教训）。
- 性能基线按最严平台执行：内存 ≤350MB、渲染 ≥30fps、逻辑帧 ≥15fps、exe ≤5G、小程序总包 20MB/首包 4MB。

### 10.5 部署拓扑

- 首发期：单集群（国内云）+ 按平台划分 adapter 实例组；抖音侧可选用抖音云（内网专线红利）与自建并存灰度。
- 扩展期：多平台共用 game-core 集群，adapter 层无状态水平扩展；监控按 平台×房间 双维度打点。
- 灰度与合规开关：功能开关（幸运系统组件、外显文案词表）全部配置化，按平台/按版本灰度。
- **热更与审核边界（v0.6 补，合规关键）**：平台二级违规明确含"线上修改产品内容为禁入类型"——热更范围必须自我设限：服务端配置（数值/词表/布局/概率）与不改变机制的美术资源差量，允许**局间结算窗口**热更（不打断对局）；**玩法机制/规则变更必须走版本提审**，严禁热更下发；此边界写入 CI/CD 流水线（机制代码包与资源包分通道，机制包出包即触发提审流程）。

### 14.2 本轮评审发现并已修复（10 项）

1. 档位价值锚点数值错误：T1"~1 元"→19 抖币实为 1.9 元；T7"~520 元"→抖音顶档实为 120 元、虎牙 52 元（顶档价值各平台差 2.3 倍，改为"各平台顶档"等效映射）；
2. 胜负判定模糊（"攻防"与"竞速"双概念并存）→ 收敛为单一胜负条件（进度条先抵龙门）；
3. 阵营人数虹吸无解法 → "人少力均"自动平衡（公示规则）；
4. 结算期 2 分钟死时间 → 内容化改造（下局预告 + 彩头预告填充）；
5. 中途加入裸奔 → 即时获得阵营平均待遇；
6. 连败增益可无限叠加 → 上限 +10%，防"故意输球攒 buff"逆向激励；
7. 无数据基线 → 5.6.1 内测校准假设表；
8. 财务测算缺退款/税/现金流/任务金 ROI → 7.5 财务现实清单；
9. 缺反刷风控与昵称过滤 → 8.5；
10. 运营人力上限缺失（100 主播 ≠ 2 人能管）→ 8.4 人力现实（1~2 人管 30~50 间）。

### 14.4 遗留风险声明（v0.6 更新）
