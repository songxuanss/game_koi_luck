# 正规渠道申请指南（软著 → 开放平台入驻 → 提案）

> Goal 交付件 D1/D2/D3 的操作手册。所有材料由 agent 生成，你只做 L3 级人工动作：实名、签字、一致性终审、提交。
> 依据：中国版权保护中心官方要求（2026-10 核实）+ 抖音/快手开放平台入驻流程。

---

## 0. 全景图与时间线

```
 Day 0          Day 1~3         Day 3~5        Day 5        Day 5 之后
 ──────         ────────        ────────       ─────        ──────────
 注册版权中心    agent 生产       agent 生成      你做一致性    等待审核
 账号+实名      repo 骨架代码    软著材料包      终审(L3)      (普通30-60工作日
 (1-3日审核)    (≥3000行+demo)  (源码PDF/       → 提交        /加急1-35工作日)
                并行:开放平台     说明书/申请表)
                入驻(抖音+快手)
```

**为什么软著不等成品**：登记的是"代码著作权"——repo 骨架 + demo 即可申请 V1.0；上线版本差异不影响（后续可登记 V2）。

---

## 1. 第一步：软著申请（D1，关键路径）

### 1.1 Day 0：你今天要做的（10 分钟）

1. 打开 **中国版权保护中心** 官网 `www.ccopyright.com.cn`；
2. 右上角**注册**账户（选"个人"身份）；
3. 按指引完成**实名认证**（上传身份证信息）——审核 1~3 个工作日，**先把这个等待期跑起来**；
4. 同日并行：注册**抖音开放平台**（developer.open-douyin.com）+ **快手开放平台**（open.kuaishou.com）开发者账号并实名（见第 2 节）。

### 1.2 Day 1~3：agent 生产代码（软著的材料基础）

软著要求**源程序 ≥3000 行**（正好覆盖前后各 30 页 × 每页 50 行）。启动 `tech-foundation` change，产出：

- `server/`：Node/TS 服务端（game-core 骨架：房间状态机/助力值经济/LiveEvent 事件模型/local-grab-adapter）；
- `client/`：Cocos demo（一个能跑的最小互动界面——**它同时是说明书截图的来源**）；
- 行数要求轻松达到（TS 类型定义 + 测试代码都算有效行）。

### 1.3 Day 3~5：agent 生成软著材料包

| # | 材料 | 规范要点 | 生成方式 |
| --- | --- | --- | --- |
| 1 | **源程序 PDF** | 前后各连续 30 页共 60 页（不足全交）；**每页 ≥50 行**有效代码（结束页 ≥15 行）；页眉=软件全称+版本号；右上角页码 1-60；页脚=著作权人姓名；A4 纵向单面黑白 | 脚本自动从 repo 抽取排版生成 |
| 2 | **用户操作手册 PDF** | 前后各连续 30 页共 60 页；每页 ≥30 行；**图文结合**：从启动/主界面/各功能模块逐个截图 + 文字说明；截图必须来自 demo 实拍（含软件名与版本号），**禁止 PS 修图** | agent 基于 demo 截图 + 方案文档生成 |
| 3 | 申请表信息 | 在线填写（见 1.5 填报要点） | agent 起草，你抄进官网 |
| 4 | 身份证正反面复印件 | 个人申请必备 | **你准备** |
| 5 | 《非职务软件开发保证书》 | 个人申请必签（勾选第一种情况+亲笔签名） | 模板下载后**你签字** |

### 1.4 软件命名（先定，全流程锁死）

**命名三原则**：以"软件/系统/平台"结尾；与内容强关联；中英文之间不能有空格。**避开"抽奖/游戏"字样**（对齐平台外显用词纪律）。

| 候选 | 说明 |
| --- | --- |
| **幸运锦鲤直播互动系统 V1.0** ⭐ 推荐 | 与玩法强关联；"互动系统"准确描述形态 |
| 锦鲤好运直播间互动软件 V1.0 | 备选 |
| ~~LuckyDrawer互动直播系统 V1.0~~ | **弃用**：LuckyDrawer = lucky draw（抽奖），与平台外显用词纪律冲突，且软著名称将出现在提审材料中 |

### 1.5 申请表填报要点（个人申请）

| 字段 | 填法 |
| --- | --- |
| 软件全称 | 与 1.4 锁定名完全一致（含 V1.0 与否以申请表为准，页眉跟随） |
| 软件作品说明 | 原创 |
| 权利取得方式 | 原始取得 |
| 著作权人类型 | 个人 |
| 开发完成日期 | demo 骨架实际完成日（真实日期，不预填未来） |
| 发表状态 | **未发表**（尚未公开上线） |
| 源程序量 | 如实填行数（与提交 PDF 结尾行数一致） |
| 编程语言 | TypeScript / JavaScript（按实际，**开发工具不算语言**） |
| 运行环境 | Node.js、Cocos Creator、Windows |
| 主要功能 | 与说明书目录一一对应：直播间弹幕互动处理、礼物效果档位映射、多阵营进度结算、自动播报控制、数据统计看板等 |
| 技术特点 | 实时事件流处理、跨平台适配架构等（与软件相关，勿写无关内容） |

### 1.6 一致性红线（驳回重灾区，提交前 L3 逐项过）

- [ ] 软件全称 + 版本号：**申请表 = 源码 PDF 页眉 = 说明书页眉 = 说明书截图内显示**，四处完全一致；
- [ ] 代码中的 `author / copyright / version` 注释：与申请人一致，**不一致的直接删除**（检索关键词：author、copyright、version、版权）；
- [ ] 源码体现的功能 ⊆ 说明书介绍的功能（**不能无中生有**，也不能有功能写了代码却说明书没讲）；
- [ ] 页码：源码与说明书各自从 1 连续编排，右上角标注；
- [ ] 截图无 PS 痕迹、无剪切痕迹；
- [ ] 所有材料 PDF 格式；A4 纵向单面；黑白。

### 1.7 提交与加急选择

| 方式 | 周期 | 费用 | 适用 |
| --- | --- | --- | --- |
| 官方直提 | 受理后 60 工作日内（不符 30 日内补正） | **免费** | 不着急时 |
| 代理加急 | 1~35 工作日多档自选 | 300~3000 元 | **推荐**（提案入驻要用，2~4 周档位性价比最高） |

> 加急代理在淘宝/知识产权代理机构均可办，选"个人软著加急"，材料包直接给他们提交。

### 1.8 等待期与补正

- 状态可在中心官网"用户中心-我的登记"查询；
- 收到《补正通知书》→ 30 日内按要求补正（逾期视为撤回）——**常见补正原因就是 1.6 清单里的项**，逐项过检可大幅降低补正概率；
- 拿到证书（或受理通知）→ 解锁开放平台"上架资质"材料。

| 平台 | 动作 | 注意 |
| --- | --- | --- |
| 抖音（首发） | developer.open-douyin.com 注册 → 个人实名认证 → 创建"直播小玩法"应用 | 个人主体需软著（受理后一般可先行推进，证书在提审前到位即可——以平台当期要求为准） |

## 3. 第三步：玩法提案（D3）

提案材料（agent 起草、你 L3 签核）：

1. 玩法说明（核心循环 12~15 分钟三阶段，方案 5.2）；
2. **数值附录**（方案 5.9 GDD 框架：助力值经济/克制环/平衡算法——平台评审喜欢有数的提案）；
3. **合规自审表**（方案附录 C 三层红线逐项勾选）；
4. 无人模式说明（Auto-Host 四子系统 + 防封三原则，方案 2.5/5.5）；
5. 美术风格稿（AI 概念图 2~3 张，风格圣经产出后取用）。

双平台同期递交（抖音首发 + 快手备援），**T0 = 首个平台提案通过日**。

---

## 4. 常见驳回/补正原因 Top 6（提前规避）

1. 名称/版本号/著作权人**不一致**（重灾区，1.6 清单）；
2. 说明书**太薄**或纯文字无截图（每页 ≥30 行 + 图文结合）；
3. 代码行数与申请表填报不符；
4. 代码内版权注释与申请人冲突（含开源协议注释未清理）；
5. 截图与申请软件不符（用了别的软件的图/设计稿冒充实拍）；
6. 功能描述"无中生有"（说明书功能在代码中无对应）。
