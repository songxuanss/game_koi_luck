## V0 验证轨（民间快速模式，2026-10-16 拍板：短期按此方式跑）

> **定位：数据工具，不是生意**（R3b 纪律）。目标是在官方流程走完前，提前验证 H1/H2 假设。

**技术路径**：`local-grab-adapter`（消费 `jwwsjlm/douyinLive` 类抓取工具的本地 WebSocket 消息流 → normalize 成 LiveEvent）→ **game-core 最小版全量复用** → Cocos demo 客户端 → 直播伴侣窗口采集推流。

```
直播伴侣官方开播(合规)
  ├─ 抓取工具:抓直播伴侣进程弹幕/礼物 → 本地WS(灰色,风险自担)
  └─ demo客户端消费LiveEvent → 画面被伴侣采集推流
```

**运作边界（R3b 逐条落地）**：
- 自播用**可弃置测试号**（≥500 粉丝满足开播条件即可）；主号与未来报白号绝不沾染；
- 熟人主播 ≤5 个复测 H1（不抽成或象征性，明确告知风险：挂非官方玩法可能留处罚案底）；
- 不做中心化数据收集（不做对账工具）——**民间分发不做，规模化分发只等官方（D1-D3）**；
- 验证周期有时限：官方提案通过（T0）后民间模式收缩为 0~1 个样板间。

**验证产出**：H1 流量曲线（7 天分时段）+ H2 破冰率初步数据 + 真实礼物事件流样本（为 game-core 数值校准供数据）——**全部结论直接喂给官方轨，代码 100% 复用**。

**与正规渠道的节奏咬合**：V0（本周启动）∥ 软著加急（Day 5 提交）∥ 开放平台入驻（Day 0~2）→ 三线互不阻塞。

## 阶段 1：技术选型与架构（与阶段 0 尾部并行，约 1~2 周）

**目标**：锁定技术栈，立起 Core/Adapter 骨架，跑通一条真实平台链路。

| 决策点 | 推荐选型 | 理由 | 方案溯源 |
| --- | --- | --- | --- |
| 客户端引擎 | Cocos Creator 3.8+ (TS) | 唯一同时满足快手 exe + 小程序双路线；H5 留口 | 10.4 |
| **构建目标（已拍板 2026-10-16）** | **原生 exe 唯一构建目标**；web 版（WebView2 轻壳）后置 | 平台文档明示路线，提案零接受度风险；1 人 + agent 先跑通单路线 | 10.4 |
| 服务端 | **Node + TS（全栈共享类型）** | 1 人 + agent 生产下类型安全红利（三端共享类型）> Go 性能；压测靠架构分帧解决 | 10.1 |
| 美术画风 | **2.5D**（非真 3D） | 外包主力档成本 + 渲染性能余量 + 为未来 web 路线保留切换自由度 | 9.2 |
| 仓库结构 | monorepo：`client/ server/ packages/shared/` | LiveEvent 类型、词表、数值配置三端共享 | 10.1/10.2 |
| 部署 | **抖音云优先评估**（内网专线/免鉴权/免备案/防 DDoS——首发即用其红利），自建云兜底 | 抖音为首发平台，10.3 的抖音云优势应最早吃到 | 10.3/10.5 |
| 数据 | 埋点字典 + 基线指标（5.6.1）先行设计 | 测试期就要用 | 5.6.1 |

**web 版后置决策的触发条件**（G2 后纳入评估，避免"看情况"变成"永不看"）：
- 云端运行成本实测：单房间 24h 云成本占该房间流水 >15% → 启动 web 版（WebView2 轻壳）评估
- 或快手小程序路线提上日程（手机开播主播供给成为重要来源）→ web 构建近直迁，顺势启动
- 评估内容：WebView2 壳平台接受度确认 + 同代码 web 构建压测（渲染≥30fps / 内存≤350MB）

**关键活动与交付物**：
- `PlatformAdapter` 接口 + `LiveEvent` 统一事件模型定义（shared 包）
- 抖音 demo 链路：token → room_id → 逐 msg_type 任务开启 → 礼物置顶 → HTTP 回调 → WS 推客户端（打通即架构验证；可选抖音云内网专线链路）
- 词表系统 + 配置中心（config-as-data）骨架
- CI 骨架：lint + 单测 + 合规词表扫描（门禁雏形）

**阶段出口**：架构评审通过（对照 Guardrails R1~R4 + Core/Adapter 约束）；抖音 demo 链路跑通。

**OpenSpec 映射**：change `tech-foundation`（repo 骨架/接口定义/CI）。

## 美术风格与质量管理（横切机制，v1.2 重写：AI agent 生成管线）

> **前提（2026-10-16 拍板）：美术产出全部由 AI agent 生成，无人力外包。** 团队角色是"美术指导 + AI 操作员"（客户端或策划兼任），负责 prompt 体系、生成筛选与一致性把关。
> 防返工原则不变：**风格锁定点后移到有数据支撑之后；锁定前所有产出低价可丢弃**（调研 + 概念图成本仅为 AI 算力）。

### 0. AI 管线的强弱项认知（管线的职责分配依据）

| AI 擅长 | AI 不擅长 → 人的职责 |
| --- | --- |
| 概念图/风格探索（快、便宜、多方向） | 风格判断与筛选（美术指导的核心价值） |
| 立绘/单位形象/场景背景/图标量产 | 跨批次风格一致性 → 锚点图库 + LoRA + LUT 统一 |
| 变体批量生成（多 seed 跑量） | 骨骼动画装配 → AI 出**分层图**，人用 Spine 装配 |
| 局部重绘精修（inpainting） | 复杂演出工程整合 → 程序化镜头 + 粒子（代码侧） |

### 1. 前置调研流程（阶段 0 内执行——AI 时代依然必须，甚至更重要）

AI 能瞬间产出任何风格，方向选错的"返工"更快但依然存在（prompt 体系与 LoRA 全部重建）。流程与 v1.1 一致：

```
 竞品画风盘点 + 平台用户分析 + 幸运符号热度   (桌面调研, wk1)
        ↓
 《美术风格调研报告》(2~3 候选方向 + 风格空位分析)
        ↓
 3 方向概念图(AI 批量生成, 仅算力成本)
 + 竞品直播间弹幕语义分析 + 小样本用户评估
        ↓
   锁定 1 个方向 → 风格圣经 v1 + Prompt 体系 v1
```

### 2. 风格圣经 → 升级为"风格圣经 + Prompt 体系"（AI 管线的真正中枢）

| 组件 | 内容 | 作用 |
| --- | --- | --- |
| 风格圣经 | 色板（hex 锁定）、造型语言（2.5D/Q 版 2.5 头身质感成人化）、光影/特效语言、UI 规范、禁区清单 | 人看的验收基准（不变） |
| **锚点参考图库** | 锁定方向后 AI 精选 10~20 张锚点图 | 所有生成的 few-shot 风格参考 |
| **Prompt 模板库** | 按资产类型分模板（单位/场景/UI/特效帧），含正/负提示词 | 量产一致性的第一道闸 |
| **负面词表** | **合规词表直接进 negative prompt**（低幼画风词、赌具意象词、违规用词）——从生成源头防，而非事后审 | 合规与风格双防线 ⭐ |
| **LoRA（视需要）** | 若风格一致性要求高，用锚点图训练小 LoRA | 跨批次风格锁定的最强手段 |
| **LUT/后处理管线** | 统一色板的后处理预设 | 最后一道一致性收口 |

### 3. AI 管线三关（替代原"外包三关"）

```
 定型关(种子关)              批次关(量产循环)            一致性关
 ───────────────           ─────────────────         ───────────────
 风格圣经 + 锚点图库         批量生成(多seed跑量)       每批资产并排
 + Prompt 模板库              → 美术指导筛选             对照锚点 review
 + 负面词表                   → 局部重绘精修             + LUT 色板统一
 + 视需要 LoRA 训练           → 分层整理(前景/主体        + 技术规格检查
 (一次性投入,阶段0末)          /背景分离供 Spine          (尺寸/分层/帧数)
                              装配)
                              → 入资产库
```

**资产库纪律**：生成图 + prompt + seed + 模型版本一并归档——可复现是 AI 管线的"源文件交付"等价物（换工具/重训时资产可追溯重建）。

### 4. 资产分级与预算（美术成本从 ~4.5 万 → ~0.6 万）

| 级别 | 资产 | 管线 | 成本构成 |
| --- | --- | --- | --- |
| **A 锚点**（hero moments） | 跃龙门、神龙、SSR 星耀鲤、主场景 | AI 多轮迭代 + 局部重绘精修 + 程序化演出 | 算力 + 美术指导时间 |
| B 量产 | 鱼苗/单位/UI 组件/常规特效 | AI 批量生成 → 筛选 → 入库 | 算力 |
| C 功能件 | 规则贴纸/榜单底板/状态图标 | 程序化生成（代码 + 模板） | 几乎为零 |

**美术现金预算**：AI 工具订阅 + 云算力 + LoRA 训练 + 字体/素材授权 ≈ **5,000~8,000 元/全周期**（vs 原外包 4.5 万）。

### 5. 验收四道（保留，形态适配 AI）

1. **一致性验收**：每批并排对照锚点图库 review（AI 批次漂移比人狠，此关权重最高）；
2. **技术验收**：分层完整性（Spine 装配前提）、序列帧规格、贴图内存预算——不合格=渲染掉帧=压测不过；
3. **合规验收**：**AI 生成内容全量人工终审**（AI 会出畸形/意外内容，负面词表防得住方向性风险、防不住单张意外）+ 图内文字过词表；
4. **风格圣经符合性**：色板/造型/禁区清单逐项对照。

### 6. 与阶段时间线咬合

| 时点 | 美术动作 |
| --- | --- |
| 阶段 0（wk1） | 前置调研三件套（竞品/用户/符号） |
| 阶段 0（wk2） | 3 方向概念图（AI）→ 锁定 → 风格圣经 + 锚点图库 + Prompt 体系 + 负面词表 |
| M1~M2 | 锚点资产多轮迭代 + B 级量产启动（AI 生成快，美术不再是排期瓶颈） |
| M3 前 | 演出资产齐：AI 关键帧 + 程序化镜头/粒子 + Spine 装配 |
| G3 后 | 升档 = 更强模型/LoRA 迭代/虚拟主持人形象（AI 生成优势区） |

> **排期红利**：AI 管线使美术从"外包排期瓶颈"变为"随用随生成"，阶段 2 关键路径让位给开发本身——MVP 周期有进一步压缩空间。

## Agent 生产模式与人类验证体系（v1.3：生产模式重构）

> **拍板（2026-10-16）：所有项目产出由 agent 生产，人力仅负责验证、测试。**
> 生产成本趋零后，项目的真实瓶颈转移为：**人类验证吞吐量 + 外部依赖周期**（平台审核/任务金/账号）。本章定义角色边界、验证分级与验证吞吐管理——这是 agent 生产线的质检制度，OpenSpec 是其工单系统。

### 1. 角色矩阵

| 产出物 | 生产者（agent） | 验证者 |
| --- | --- | --- |
| 代码（client/server/adapter） | coding agent（OpenSpec change 驱动） | L0 CI + L1 agent 交叉 review + L2 人抽验 |
| 美术资产 | AI 生成 agent（美术章 v1.2 管线） | 一致性/技术/合规四道验收（人终审） |
| 文档（方案/提案/调研） | agent | L2/L3 人签收（提案=对外承诺，L3） |
| 测试用例与执行 | agent 生成 + agent 执行 | L0 结果自动判定 + L2 人看报告 |
| 数值/词表/配置 | agent 起草 | L2 人审批（数值方向是设计决策） |
| 运营数据看板/周报 | agent 生成 | L2 人研判 |

### 2. 人类专属清单（agent 不可代劳——法律主体与外部接口行为）

- 平台注册/主体认证/协议签署/软著申请；
- 提案提交与平台、公会的所有外部沟通；
- 资金操作：任务金充值、服务器采购、结算确认、发票；
- **合规终审**（提审材料签署前的人为把关）；
- **决策**：三级灯判定、Pivot/止损、Goal 修订、上线发布；
- 自运营账号的开播管理（可脚本化执行，但账号安全责任在人）。

### 3. 验证分级（每个任务的必填属性）

| 级别 | 执行者 | 适用 | 节奏 |
| --- | --- | --- | --- |
| L0 自动 | CI | lint/单测/词表扫描/性能基准/合规检查自动化 | 每次提交 |
| L1 agent 交叉 | 第二个 agent review | 代码 diff、文档一致性、数值自洽 | 每次提交 |
| L2 人类抽验 | 人 | 里程碑产物：架构决策、数值方向、风格锚点、测试报告研判 | 每里程碑（批量验收） |
| L3 人类全验 | 人 | 合规红线、平台提审材料、资金、对外发布、Goal 修订 | 事件驱动，100% 人看 |

### 4. 验证包制度（保护人类吞吐量的关键机制）

**agent 的每个 change 完成时必须附"验证包"**，人类先看包、再抽验：

```
 验证包 = 自测报告(全部测试结果+证据)
        + 合规自查(对照 config rules 逐条勾选)
        + 风险声明(本次改动可能影响的边界)
        + 验证级别建议(L2/L3 + 抽验点建议)
```

### 5. 预算分配（v1.3：agent 生产模式，15 万硬顶不变）

**现金构成变化**：开发人力零现金、美术 ~0.6 万 → 现金主力 = AI 工具订阅 + 云资源 + **任务金弹药**。

| 阶段 | 现金构成 | 预算 |
| --- | --- | --- |
| 0 需求澄清 | AI 算力（概念图）+ TTS 测试 + 调研杂项 | 4%（~0.6万） |
| 1 技术选型 | agent 订阅 + 服务器/工具 | 3%（~0.5万） |
| 2 研发 MVP | AI 全管线（美术算力 0.3）+ 云资源 1 + 缓冲 1.1 | 16%（~2.4万） |
| 3 测试+内测 | 任务金首轮 + 挂机主播激励 | 17%（~2.5万） |
| 4 上线验证 | **任务金续投 + 干预储备（弹药主体）** | 60%（~9万） |

> 任务金受 ROI 纪律约束（8.6：ROI<1 连续 2 周停投），弹药足但不开胡乱扫射。
> **周期红利**：agent 生产使 MVP 有 4~6 周压缩空间，但瓶颈转为人类验证节奏（批量验收制）与平台审核周期——排期按保守值报，红利作缓冲。

### 6. 风险声明：agent 生产模式的特有风险

| 风险 | 对策 |
| --- | --- |
| agent 产出的合规瑕疵人没兜住 | L3 清单刚性（提审/资金/发布必须人过）；验证包强制合规自查 |
| agent 间错误传播（上游错→下游全错） | L1 交叉 review 独立性（review agent 不看生产 agent 的结论，只看产出） |
| 人类验证成为吞吐瓶颈，产出堆积 | 批量验收节奏 + 验证包制度 + 验证分级（不是所有产出都上人） |
| 数值/设计方向被 agent 带偏 | 数值方向、风格锚点定 L2 必审——设计决策永远是人的 |
