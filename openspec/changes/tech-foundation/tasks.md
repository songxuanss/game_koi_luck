## 3. core 内核（阶段:研发）

- [x] 3.1 【L0】纯函数内核 `step(state, input, config)`：房间状态机（蓄势→攻防→鸿运→终局潮汐→结算）、时间戳驱动（禁实时钟）。验收：零 IO 依赖（依赖扫描测试）+ 空事件走完一局
- [x] 3.2 【L0】助力值经济：T0~T7 结算（助力值记贡献、进度按档位规则）、单位/增益效果、T6 名额（全局 3/人 1，超额降级仍有效果）、T5+ 边际递减。合规链接：C-平台"礼物均有确定效果"、C-反催氪"单用户大额名额限量"。验收：单测覆盖每档结算 + 组刷 + 单件礼物进度 ≤12.5%
- [x] 3.3 【L0】阵营平衡：人数因子 + 逆流（20% 触发/10% 解除）+ 连败增益封顶 10% + 克制环。验收：单测覆盖 7:3 加权、临界触发/解除、封顶、三向克制
- [x] 3.4 【L0】胜负与结算：进度达 100% 即胜（含终局潮汐）、结算快照（胜方/贡献榜/气氛榜/个人贡献/关键先生/幸运星确定性发放）。合规链接：C-法律"随机产出不可交易"（内核无任何交易接口）、C-反催氪"零金额显示"。验收：随机事件序列属性测试——不存在其他终局路径；对外输出无货币字段
- [x] 3.5 【L1】RoomManager 外壳（server）：房间生命周期、配置热更新（下局/立即）、快照广播（100ms 节流合并）、自动下一局。验收：5000 条随机事件压入，快照序列一致，房间/订阅清理无泄漏
- [x] 3.6 【L0】管道压测脚本 `npm run loadtest`：单房间 1000 QPS 混合流量 × 30s，统计投递丢失与"入站→广播"延迟 P995（补 live-event-pipeline 性能规格的承接任务；全局 4200 QPS 与真实网络压测后置至 compliance-testkit）。验收：丢失 0（去重除外）、P995 < 1s，报告写入验证包
