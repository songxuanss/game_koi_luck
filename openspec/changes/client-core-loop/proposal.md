# Proposal: client-core-loop

## Why

`tech-foundation` 已证明对局链路、双布局与基础性能可用，但当前画面仍是灰底、圆点和文字占位，无法承担直播间的三秒理解、持续观看与事件高光。本变更在不改对局规则的前提下，将客户端升级为可内测的国潮夜河演出，并用自动化护栏保证合规与性能。

## What Changes

- 建立「流光国潮」视觉系统：原创山水、珠光锦鲤、鎏金龙门、琉璃 HUD 与现代 CJK 字体，而非通用卡片界面或几何占位。
- 用持续游动/摆尾、实际推进冲刺、归因飘字、水波、充能脉冲和阶段色彩表现快照；礼物、全民锦鲤潮、克制、逆流、跃龙门与结算拥有分级反馈。
- 强化三秒理解与免费参与：阶段口令、双方状态、集体充能、贡献/气氛信息和关键先生结算；不展示金额，不生成消费指令。
- 保持布局档案、本地 demo 与网络源兼容；静态层只建一次，动态对象设硬上限，延续 ≥30fps、≤350MB 基线。
- 扩充纯逻辑与 Cocos 行为级测试，并在真实编辑器完成视觉及 30 分钟性能验收。

## Capabilities

### Modified Capabilities

- `client-presentation`: 从占位 demo 升级为完整核心循环呈现，新增视觉系统、演出队列、参与引导、结算高光和性能约束。

## Impact

- 主要代码：`client/assets/scripts/`、布局档案及客户端测试。
- 不改 `packages/core` 的胜负、数值与随机规则，不接平台 SDK，不引入新运行时依赖。
- 关联 G2 与 H1/H2/H3：提升前 30 秒理解和观看反馈，为 H2 的 Auto-Host 对照实验提供稳定视觉基线；不得以视觉升级替代真实流量实验。

## Guardrails 自检

| 规则 | 自检结论 |
| --- | --- |
| R1 法律+平台规则 | 无交易、回兑、现金或实物回报；随机外观仍只消费 core 结果 |
| R2 反催氪 | 不显示金额、不播消费指令、不制造定向焦虑；所有新增文案过词表 |
| R3/R3b | 演出由实时快照和事件驱动；demo 仅用于验证，官方轨仍可复用 |
| R4 预算 | 程序化 2D 资产，无新增订阅或外包支出 |
| 合规三层清单 | 法律层无价值回报；平台层保持唯一随机外观来源；反催氪层保留免费高光和非金钱承认 |
| 阶段门关联 | 属 G2 的 M2；失败时仅回滚呈现层，不影响 core 与适配器 |
